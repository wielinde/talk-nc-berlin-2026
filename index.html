Deep integration of Nextcloud and OpenProject

Let's have a look what it really means to deeply integrate two systems.

Nextcloud is mainly a file storage platform

Real challenges for an organisation

  • Problem 1: "Where are the files for my task?"
  • Problem 2: "Does everyone in my team have access?"
  • Problem 3: "I want similar projects to easily follow the same structure"
Exactly what teams migrating away from Jira and Confluence run into all day long.
  • There are almost no files without a task
  • There are almost no tasks without files
  • There is almost no team without a shared folder somewhere
  • Repeating projects, tasks, files and folder structures need templates

Integration wins over feature duplication

  • OpenProject has very basic file management, e.g. attachments
  • Nextcloud has very basic task management, e.g. Deck
  • Integration allows both to focus on their own core strengths
  • No feature parity race, no lock-in between the two

Seamless Cross Application User Integration
Supporting Standards: OAuth 2 Token Exchange and SCIM


This pushes integrations of independent vendors in the open source eco-system massively forward. Use cases like our super deep bi-directional integration with Nextcloud become so much smoother. App suites like Nextcloud Hub only find adoption if cross application user integration is solved. It is complex and expensive. It needs to get simpler and out of our way. Fortunately there are open standards for OIDC and Token Exchange for delegated access, and for user provisioning via SCIM.
